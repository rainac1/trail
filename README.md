# Trail

[English](README.en.md) | 中文

Windows 全屏透明叠加层：在光标身后显示一串残影。鼠标每回报一次，就多一个尾迹点；启动时自动
检测主显示器的单帧刷新时间作为尾迹寿命，每个尾迹点只显示一帧就消失。尾迹长度取决于光标在这
段时间内移动了多远。

运行期间会持续被动监测 DWM 在主显示器上的实际帧时间：当帧时间偏离启动基准（例如播放视频触
发 VRR 降频/抖动或 DWM 合成掉帧）时，自动清空尾迹并暂停提交；待帧时间重新贴合基准后自动
恢复渲染。

## 构建

前置：Windows 11（21H2 及以上）、Visual Studio 2022+（“使用 C++ 的桌面开发”工作负载，含 Windows 11 SDK 10.0.22000+）、CMake 3.16+。

```bat
build.bat            REM Release
build.bat Debug      REM Debug
```

产物：`build\trail.exe`（Ninja）或 `build\Release\trail.exe`（MSBuild）。

## 运行

```bat
build\trail.exe
build\trail.exe --sprites 96
```

| 参数 | 含义 |
|---|---|
| `--sprites <n>` | 最多同时显示多少个尾迹点，默认 64 |
| `--log` | 开启诊断日志，写入 exe 同目录的 `trail.log`（默认关闭） |

`Ctrl+Alt+Q` 退出（若热键已被其他程序占用则直接退出；不支持重复启动多个实例）。

## 已知限制

- **只画主显示器**；其它显示器上没有尾迹。显示器分辨率、刷新率、缩放比例或数量变化后需要重启。
- **同时最多 64 个尾迹点**。高回报率鼠标在较低刷新率下，最早的点可能会被提前挤掉；如果尾迹看起来比实际
  移动短，把 `--sprites` 调大。
- **持续不间断移动超过 `--sprites` 个采样点时，偶尔最新的一小段尾迹会被较旧的点盖住**；
  停顿清空后会重置顺序，一帧尾迹下几乎看不出来。
- **显卡驱动重置、睡眠唤醒等情况可能让尾迹整体消失**；程序会自动恢复，恢复前有一小段空白。
- **需要支持 DirectX 11 的显卡，并且 Windows 的桌面合成保持开启**（默认开启）。

## 日志

默认不写日志文件。传入 `--log` 时会在 exe 同目录写入 `trail.log`（程序运行时也能查看），
记录启动失败、显卡异常后的自动恢复、显示器变化与活动期统计；设置 `TRAIL_NO_UI=1` 可以关闭
启动失败时的弹窗。
